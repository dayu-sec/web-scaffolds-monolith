# 客户端产品 UI 基线

本文档定义当前脚手架的产品定位与视觉、几何、可访问性目标契约。它是项目级补充；通用的 UI 工程实现、组件选择和表单规则继续遵循目标仓库的工程约定与现有源码契约。

本脚手架面向**外部客户与终端用户**（客户门户、面向客户的 SaaS 界面、消费级应用），不面向高密度管理控制台。它与内部运营后台共享同一品牌蓝和同一套 Shell，但密度、材质与尺寸档位不同，不得互相套用。

设计原型只提供证据，不构成本脚手架的规范：原型中的页面结构、固定宽度比例、阶段性配色和交互取舍都需要重新评审后才可进入这里。

## 基础布局

顶栏 + 左侧菜单 + 右侧内容工作区。内容工作区占据 Shell 剩余空间，**不设内容最大宽度、不做居中收窄**；需要限制阅读宽度的长文本由具体页面在自身容器内处理。

布局随视口降级：窄屏侧栏收起为抽屉，顶栏隐藏面包屑与居中区，内容内边距收敛到 24/16px。横向内容（宽表格、图表）在自身容器内横向滚动，页面本身不产生横向滚动。

## 视觉基线

### 颜色

冷中性画布 `#f4f7fc` + 克制科技蓝 `#2563eb`。按 60-30-10 控制强调色面积：60% 画布与留白，30% 工作面与中性文本，10% 强调色与状态色。蓝色只承担主操作、当前项与焦点，不铺满侧栏、卡片底色与图表全域。

状态色与品牌蓝在色相上明确区分，且不得作为唯一的状态识别方式，需同时提供文字或图标。实心状态填充按 WCAG 2.2 AA 正文 4.5:1 校准；指示条、图标与 12% 弱底可使用 `--chart-*` 中保留的原始低饱和色相。

### 画布与背景光晕

侧栏与内容工作区共用一块连续画布：光晕铺在 Shell 根上横跨两者，侧栏与内容区自身都不铺实色，只靠 1px 弱边界分隔。

光晕强度上限由对比度决定，不由观感决定。次要文字与链接直接压在这层背景上，**5% 是实测下 `--muted-foreground` 与 `--primary` 仍能保持 4.5:1 的最大值**（实测最低 4.52）。调高会先击穿次要文字，任何调整都必须在混合后的背景上重新实测，而不是在纯画布色上估算。

### 侧栏菜单

菜单项高 44px、圆角 `--radius-lg`、字号 14px、字重 500。选中项使用**实心工作面浮起于画布之上**（白底 + `--primary` 文字 + 字重 600），而不是主色弱底填充。字号与字重由 `--dy-sec-shell-menu-item-*` 令牌拥有，不在样式表中写死字面量。

### 圆角

`--radius` 基准 14px，派生：`sm` 8px（标签、小元素）、`md` 11px（按钮、输入框）、`lg` 14px、`xl` 20px（卡片、模态框、抽屉）。卡片内元素的圆角必须小于外层卡片。

### 阴影与材质

`--shadow-soft` 用于内容层卡片，`--shadow-active` 用于选中态，`--shadow-overlay` 用于浮层。全部为大扩散半径、低不透明度；禁止短硬阴影与粗实线深色边框。选中态使用主色描边加弥散光晕，而不是加粗硬框。

界面只允许背景层、内容层、浮层三层空间。`--blur-overlay`（20px）只用于顶栏与浮层；主内容区、长文本、表单保持高不透明度。使用玻璃拟态处必须提供 `backdrop-filter` 不可用时的不透明回退。

### 留白

4px 微单位、8px 主节奏。亲密性关系 6px，分组之间 24px，页面区块 32–48px。内容工作区不设最大宽度，随视口铺满剩余空间；面包屑与主内容共享同一条对齐线。

## 可访问性目标

以下为交付门槛，不是建议值：

- 正文对比度至少满足 WCAG 2.2 AA（正文 4.5:1，大字号 3:1），玻璃拟态区域需在真实内容背景上实测。
- 可点击区域不低于 36×36px，触控场景不低于 44×44px；扩大点击框而非仅扩大图标视觉尺寸。
- 所有交互状态需有可感知反馈，`:focus-visible` 必须保留可见焦点环。
- 状态、风险与选中不得只依赖颜色。
- 遵循 `prefers-reduced-motion`；动效时长 150–250ms，统一使用 Ease-Out 类型曲线。

## 页面实现约束

- 根路由不预置业务 DOM。脚手架只提供 Shell、令牌与几何，不把某种页面结构固化为生成范式；真实视图放入 `apps/web/src/views/components/<domain>/`。
- 页面不各自维护外层留白或平行色板；工作区留白由 Shell 令牌拥有。页面可在自身容器内限制长文本阅读宽度，但不得给整个工作区加最大宽度。
- 首屏需回答"我在哪里、我拥有什么、我下一步做什么"，并包含一个明确的主行动；一屏通常只保留一个实心主按钮。
- 每个数据区域都需设计完整状态集合：加载中、初次为空、筛选后空结果、部分失败、错误、权限不足、数据过期。
- 界面文案以用户为主体，使用第二人称描述其资产、状态与待办动作，不使用服务方内部视角的第三人称称谓，也不暴露内部模块名与状态机内部值。

## 验证

UI 变更除 `pnpm check`、`pnpm lint`、`pnpm test`、`pnpm build` 外，还需在真实浏览器中确认：

- 实测对比度、点击框尺寸与键盘焦点可见性，而非在设计稿上估计。
- 覆盖浅色与深色、100% 与放大缩放、窄屏与移动端视口、长中文与长标识、空值与多行内容。
- 确认页面不产生横向滚动，固定顶栏不遮挡焦点与内容，带阴影卡片不被滚动容器裁切。

无法使用真实浏览器与真实设备时，只能报告静态与构建证据，不得宣称尺寸、对比度或视觉验收完成。
